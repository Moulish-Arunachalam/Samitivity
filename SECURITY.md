# Security and privacy

Samitivity runs as the current user. It contains no application network client, network listener, telemetry, cloud integration, updater, plugin system, arbitrary script execution, keyboard logging, or privileged keyboard interception. Only explicitly registered modifier shortcuts are observed. Windows Media Foundation is called with managed local file paths, never a URL. Import rejects UNC/mapped network paths. The app does not change system volume.

Audio stays as original local files under the current user's LocalAppData profile, using ordinary Windows account permissions. Files are **not encrypted by Samitivity**. Another program running as the same user, an administrator, malware, a backup agent, or a person with disk access may read them. Windows/device encryption and secure account access remain separate concerns. Cloud backup or profile redirection configured outside the application is outside this boundary.

Do not commit real voice notes or signing credentials. `.private/`, build output, audio extensions, and certificate formats are ignored by Git, with narrow exceptions for synthetic fixtures. Ignore rules are a convenience, not an exfiltration safeguard: inspect `git diff --cached --name-only` before every push. Public CI never accepts a private bundle. A gift installer containing voice notes is itself sensitive; distribute it privately and delete unnecessary copies.

Source and destination filenames are never interpolated into a command or script. The only process launches are a fixed application executable and Windows Explorer with an argument-list folder path. Task/Startup registration uses Windows COM APIs, not configurable commands. Category folder names are GUIDs; managed filename prefixes prevent reserved device names and collisions. Reparse paths are rejected to reduce accidental escapes. Same-user file replacement races are not an isolation boundary against hostile local software.

Native media decoding is an attack surface. Import fully decodes accepted files with bounded application buffers and rejects decoder errors, unsupported formats, empty streams, excessive duration, and oversize files. This does not sandbox Media Foundation or guarantee detection of every malformed stream. Import trusted personal recordings; maintain Windows security updates. No codec packs are downloaded.

Normal playback errors appear as bounded status text rather than repeated notifications. Fatal diagnostics retain only the most recent exception type, HRESULT, and timestamp. Audio bytes, transcripts, credentials, filenames, and shortcut keystrokes are not written to logs. Filenames are shown in the local management UI as requested.

Startup is disclosed in the installer and Configure status. The scheduled task is visible and unelevated; fallback is a normal Startup shortcut. Uninstall removes startup integration and binaries, preserving personal notes. No Defender exclusions, SmartScreen bypasses, security-setting modifications, or concealed persistence are included.

Dependencies use exact versions and checked-in NuGet lock hashes. CI actions are pinned to commit SHAs. The Inno compiler download is pinned to 6.7.3 and checked by SHA-256 and Authenticode publisher before execution. .NET SDK is pinned in `global.json`; runtime and dependency security fixes require an explicit rebuilt installer because there is no auto-update. Revisit these pins before distribution and periodically while supporting the gift. Build-host tools and package restore contact their official services; that is separate from the offline recipient application.

Signing can establish publisher identity but cannot guarantee SmartScreen reputation. Use a legitimate Authenticode certificate or eligible Microsoft signing service; protect credentials outside source control, sign application binaries and the final installer, and timestamp signatures. Never ask the recipient to disable antivirus. Test the exact final download with default Defender and SmartScreen settings.
